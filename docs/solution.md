# 方案文档

## SOP 分层

```text
第一层：通用准入
  └─ whyai 是否可用、是否连接正式 Gateway、是否具备本次权益

第二层：核心场景
  ├─ 课程到工作
  ├─ Partner 协作交付
  └─ 稳定流程封装

第三层：原子 SOP
  └─ 课程研究 / 课程应用 / 课程查询 / Partner / 执行 / 对话
```

第二层只编排阶段与判断点；第三层才放单个阶段的具体操作。因此既能让完整任务不漏环节，也不会让单步查询加载整条工作流。

## 核心工作流

```text
真实问题
  → 课程研究：方法卡
  → 课程应用：小验证
  → Partner/任务执行：形成结果
  → 会话与资产：复盘、保存、复用
```

用户先从 `SKILL.md` 选择层级：完整任务进入对应核心场景，单步任务进入原子 SOP。课程类任务若只做一个阶段，先进入 `references/sops/learning.md`；若需要“课程方法 → 真实任务”闭环，直接进入 `references/sops/scenarios/course-to-work.md`。

## 方法卡

方法卡是课程研究与真实工作的接口。它必须包含：问题、关键动作、判断信号、课程材料、适用边界和下一次小验证。没有方法卡时，课程研究还未完成；没有小验证时，不能把课程方法称为已适用。

## 资料原则

- `references/` 只保存能改变运行决策的 SOP、官方资料整理和运行时观察。
- 课程目录、账号、身份、会话等个人数据不提交到公开仓库。
- `docs/` 保存设计取舍、方案、架构和迭代历史，不进入运行时加载链。
