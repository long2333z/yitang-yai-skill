# YAI 一堂第一课：把它用进工作

## 三层模型

| 层 | 官方表达的重点 | Skill 设计约束 |
| --- | --- | --- |
| 课程与知识 | 将课程、方法、案例变为可调用的知识；先检索/训练，再结合问题。 | 先做方法与来源校准，不能让交付任务越过知识缺口。 |
| Partner 协作 | 复杂问题要补足上下文、背景、意图、尝试与数据；T/C/P/R 有不同分工。 | 用任务类型和首轮任务契约路由 Partner；保留人工判断。 |
| CLI/工作流 | 在授权范围内把知识、作业、笔记、对话连接进工作系统；稳定流程才能封装。 | 先验证 CLI 可用与权限；只有被反复验证的流程才进入 SOP 或自建 Partner。 |

## 关键做法

下方“落点”保留了快照整理时的历史编号；当前结构请从 [运行资料索引](../../references/index.md) 进入。

### 1. 随聊随调

- 用关键词、方法或框架向知识库检索；分支可比较不同路径，降低单一答案带来的偶然性。
- 提示词中的“去搜索知识/课程方法”只是在请求补上下文，仍要检查回答是否真的给出了相应来源和适用边界。

**当前落点：** [课程研究](../../references/sops/course-research.md) 在任务前产出方法卡；[对话与故障](../../references/sops/conversation.md) 用分支处理真实的备选路径，而不是重复生成。

### 2. 先训再聊

- 复杂问题先围绕知识、数据或工作方法建立共同理解，再进入具体任务。
- 当知识范围/边界不清时，应先训练、验证、追问，不能直接给结论。

**当前落点：** [课程应用](../../references/sops/course-application.md) 把“方法卡能指导下一步”设为进入真实验证的门槛。

### 3. 存成资产

- 可复用的答案、推理、报告和材料应沉淀为个人资产。
- 资产应服务于下次任务的明确复用场景，不能只做无上下文的收藏。

**当前落点：** [任务执行](../../references/sops/execution.md) 规定资产的复用条件；[对话与故障](../../references/sops/conversation.md) 规定导出、分享前检查。

### 4. 拉满对话与协作接力

- AI 需要足够的上下文，且不应替人独自作决定。
- 教学可澄清“学什么”，咨询可拆解方案，实践用于交付，研究用于归纳；交接时带入已验证事实和上一阶段结果。
- 多来源/多 Agent 的整合仍应放置少量但明确的复核节点。

**当前落点：** [Partner 工作](../../references/sops/partner.md) 建立任务契约、交接包和人工复核点。

### 5. CLI、Agent 与工作流

- 官方把 CLI 描述为把课程/笔记/对话等授权信息接到工作流的方式；有影响的动作应先报告能力、征求确认。
- 课程中的“可封装为 Skill/Agent/应用”是稳定流程后的方法，不是任何场景都应自动化的承诺。
- 不应用 AI 代写作业或污染个人数据；适合做整理、结构化和排版辅助。

**当前落点：** [环境准入](../../references/sops/access.md) 先验证命令、身份、权益和只读调用；[Partner 工作](../../references/sops/partner.md) 只在稳定、可测、边界清楚时设计自建 Partner 或工作流；写入、上传、分享、删除走明确授权。

## 可封装判定门槛

将流程写成长期 SOP 或自建 Partner 前，须同时满足：

1. 同类任务已反复出现，目标与输入边界稳定；
2. 关键步骤、确认点、输出标准可以说清；
3. 已用真实小任务验证过，知道失败/缺资料时如何退出；
4. 有资料、隐私、分享和写入的授权边界；
5. 保留人为业务判断与最终验收节点。

否则应继续使用一次性协作流程，而不是过早把不稳定的推理固化为自动化。
